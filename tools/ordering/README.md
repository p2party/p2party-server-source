# Certified ordering of P2PARTY transfers

This local experiment lets a fixed committee agree on the order in which to execute signed native transfers. Each validator stores complete batches and signs its own votes with a post-quantum key. The signaling server's public Testnet 1 RPC still uses its existing PostgreSQL sequencer. [Public validator](../../src/ledger/README.md)

A fixed stake-backed epoch can also derive voting power from native signed bonds, close after a round-based delay and verify an owner withdrawal. [Stake-backed epoch and reproduction](stake-epoch.md)

## Run the experiment

From the server repository with Node 26.13.1, run the following command. The fixtures create four separate ML-DSA-65 keys and temporary SQLite journals on one machine.

```sh
node --test tools/ordering/ordering.test.mjs
```

The tests cover a silent committee member, competing proposals for one author and round, duplicate deliveries, reordered certificates, missing ancestors, recovery of an earlier anchor, skipping an unreachable anchor and storage across restarts. The storage race runs two Node workers sharing a journal through independent SQLite connections. Candidate envelopes in these ordering tests exercise wire and commitment checks. Native execution requires the full transaction verifier and deterministic state replay.

Run the native integration to reproduce a transfer, its certified receipt and a wallet proof of the resulting unspent unit. The browser SDK has a separate loopback experiment for purchasing a multi-relay route and collecting signed forwarding receipts. [Native replay and wallet proofs](native-replay.md) · [Browser relay experiment](https://github.com/p2party/p2party-js/tree/research/multi-relay-payout-local/docs/e2e/volunteer-relay)

## What validators vote on

1. **Pin the committee.** `makeCommittee({version: 1, chainId, genesisHash, epoch, operators})` accepts canonical public SPKIs with distinct operator identities. Sorting by existing operator ID gives all replicas the same member indices. A committee has `n = 3f + 1` members, with 4, 7, 10, 13 or 16 supported. The committee ID binds the chain, canonical genesis hash, epoch, roster and signature suites. The fixed committee assumes at most `f` Byzantine members. Choosing a roster and establishing operator independence require external agreement.
2. **Store a batch.** Narwhal separates data dissemination and storage from the choice of a transaction order (Danezis et al., 2022, §3). In this experiment an author signs its round, index, sorted certified parents and an ordered list of up to 16 native move IDs. Round one has no parents. Each later round requires at least `2f + 1` distinct authors from the preceding round. Each voter checks signatures, ancestry, exact wire lengths, chain and every native move ID before committing its signed storage acknowledgment and the complete payload to SQLite. The native ID hashes the existing signed transfer, including the recipient's owner commitment. A holder can return the bytes through `storedProposal(vertexId)` even if the author disappeared before collecting a certificate. Acknowledgments from `2f + 1` different validators certify the vertex. [Native transfer encoding](../../clients/evm/src/wire.ts)
3. **Order the anchor and its causal history.** The commit rule follows the partially synchronous Bullshark specification (Spiegelman et al., 2022b, §2, Algorithm 2). Even rounds designate an anchor author in rotation. A certified vertex at even round `r + 2` directly commits the round-`r` anchor when at least `f + 1` of that vertex's certified parents link to the anchor. A replica walks back from each linked anchor to recover earlier leaders, then emits their previously unordered histories from oldest to newest. It sorts vertices by round, rotates the starting author within each round, preserves signed batch order and emits each native move ID once. With a given anchor sequence, every observer can reproduce the same candidate prefix without a local arrival timestamp.
4. **Certify the executed result.** A validator passes its locally committed cumulative candidate prefix to its trusted replay routine. This routine must apply the same native authorization, spent-unit, expiry, weight and commitment rules from the pinned genesis. The first accepted spend determines an input's outcome. `attestExecution(validator, anchorId, replay)` signs the returned height, ordered receipt root and sparse state root, along with chain ID, genesis hash, committee ID and anchor ID. `collectExecution` combines `2f + 1` distinct signatures on exactly that checkpoint. `verifyExecutionCertificate(committee, expected, cert)` authenticates it against the wallet's pinned context. The verifier checks signatures. Its assurances depend on the signers running the correct replay. Receipt inclusion and an unspent output each require their own proof against the corresponding certified root.

The signatures for authorship, storage and execution use separate versioned SHA-512 domains, fixed-width fields and signer indices. For a given committee, any two quorums intersect in at least `f + 1` members. A correct validator signs at most one storage candidate per author and round and one state result per committed anchor. It durably records these decisions before returning a signature. Open an existing journal with `new Validator(committee, key, path)`. Supply `{create: true}` only for first initialization with a fresh key. Restoring an earlier journal or cloning a key into a second writable journal invalidates the one-vote assumption.

## Remaining work

The harness supplies the round scheduler and message delivery. Missing certified parents cause admission to stop until the caller obtains them and retries. The next network milestone requires authenticated peer delivery, fetching missing data from signers, bounded buffering, round advancement and timeouts, storage retention, independently operated validators, and fault measurements across machines. The current implementation retains every certified vertex and replays the journal on startup. The full Bullshark paper also describes an asynchronous protocol with a shared coin (Spiegelman et al., 2022a, §§3–5). Async fallback, certified changes between stake committees and public RPC cutover remain future work.

Predictable rotation removes a permanent lowest-index tie break. The schedule and the order inside an author's batch remain observable and selectable. Fairness and censorship resistance need separate evaluation, including competing payments for the same input. Mysticeti-C uses an uncertified DAG (Babel et al., 2025, §III). In a 13-validator evaluation of Mysticeti, Mirzaei and Amiri (2026, §§3, 5–6) found that a fixed index favored lower-index validators when ordering same-round transactions. Their preprint proposes an unpredictable per-commit tie break, which would require an agreed randomness source.

Starfish pushes headers and Reed–Solomon payload fragments, then derives data-availability certificates from the DAG (Polyanskii et al., 2026, §5). Its bandwidth and recovery costs offer a comparison for P2PARTY’s full-batch storage once measurements across machines are available.
