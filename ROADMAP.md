# Operating evidence and roadmap

## Messaging

The public 0.2.0 deployment passed a two-browser file transfer over a direct WebRTC connection and another with relay-only ICE. Checking both paths exercises different infrastructure. A healthy signaling endpoint can authenticate peers while a broken TURN listener still prevents a transfer on restrictive networks. Keep both paths in the release checks. [P2Party](https://p2party.com) · [WebRTC SDK](https://github.com/p2party/p2party-js) · [Relay operations](deploy/README.md#relay-capacity)

The PostgreSQL 17.8 to 19.0 cutover preserved the application tables, roles, grants, signed identity data and verified TLS. The retained old cluster is a rollback point only up to the first new write. Release preparation also checks the staged executable, worker environment and bounded database migration before reopening traffic. [Database cutover and rollback](deploy/postgresql-upgrade.md) · [Release exercise results](deploy/rehearsal/results/README.md)

## Native ledger

| Stage                    | What participants can verify                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Testnet 1 in 0.2.1       | A wallet can pin the public genesis, request one valueless unit, sign a transfer using either enabled suite, read the receipt and recover the same receipt after a lost response. Each owner commitment can receive a unit once. A single PostgreSQL-backed validator orders spends. [Genesis and grants](deploy/testnet/README.md) · [Wallet examples](clients/evm/README.md) |
| Independent verification | Define authenticated history and state commitments, inclusion and consistency proofs, independent replay and peer synchronization. Test recovery, equivocation detection and agreement across separately operated nodes before promising multi-validator availability.                                                                                                         |
| Consensus and governance | Specify validator admission, stake accounting, fork choice, finality, evidence and recovery rules. Establish how operators and users adopt upgrades, resolve incompatible histories and rotate keys. These design decisions remain open.                                                                                                                                       |
| Currency decisions       | The testnet units have no monetary value. Issuance, denomination changes such as splitting and joining units, economic parameters, governance authority and any mainnet launch require separate decisions, security review and operating evidence.                                                                                                                             |

Native verification checks who may spend and preserves a unit's weight. A database transaction orders accepted spends and prevents a concurrent second spend. The current trust boundary includes the operator's database and availability. A local committed height provides a receipt lookup position. Consensus finality and cryptographic proof of a complete history require the later stages above. [RPC and storage guarantees](src/ledger/README.md) · [Native verification source](https://github.com/ondemos/libdemos/tree/243a5dbbf4cb95507bb1104a47ad46ad3ed1e7a0/ledger)
