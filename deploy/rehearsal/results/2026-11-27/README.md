# Signaling 0.2.0 release rehearsal

The 0.1.4 baseline ran protocol 4. After the upgrade, the worker and the TLS endpoint through Caddy both returned version `0.2.0` and protocol `5`. The clean x86-64 release ELF built with Bun 1.4.5 had SHA-256 `26831df7f68c61d8ad16d6e6f2529c62341a6d2afd12854a22a7c8093bc7b9e9`.

| Revision                                   | Role                                                                                                                                                                                                    |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ecf691a957b22549dafe30c15f93a9623ac1d978` | Release 0.1.4 installed with its own playbooks and seeded before taking the snapshot.                                                                                                                   |
| `759ce4573d35e4bc75eb52979c2deb71087f1a49` | Release source for every candidate deployment. Its committed rehearsal driver ran the fresh installation, host Bun digest failure, and both migration failures.                                         |
| `99a4760213c4b1e404ee55e689ea7d679e1540a3` | Rehearsal driver for the clean upgrade, invalid configuration, repeat deployment, artifact reuse, and operator Bun checks. It keeps Ansible's delegated temporary modules outside the release checkout. |

The guest used Ubuntu 24.04 arm64, PostgreSQL 16.15, Caddy 2.6.2 and Prisma 7.10.1. The controller used ansible-core 2.22.0 and `community.postgresql` 5.1.3. The guest executed the release ELF with Rosetta. In this guest the worker identity check hashed the mapped executable inode. Native hosts use `/proc/<pid>/exe`. Ansible contacted the guest through loopback. The local Caddy CA, TURN certificate and read-only loopback mirror for the SHA-pinned Bun archive stand in for public infrastructure.

Coturn listened on 443 and 3478. The test paused Caddy during the coturn check because the two production roles share a single guest here. Caddy was restarted and again served 0.2.0.                                 |

The driver revision also passed `bun run check` with a separate disposable PostgreSQL 18.7 cluster. All 341 tests across 55 files ran successfully, including the two-worker and migration tests.
